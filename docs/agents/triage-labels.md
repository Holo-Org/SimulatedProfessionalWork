# Triage Labels

The skills speak in terms of triage roles. This file maps those roles to the repo's `01.status:` GitHub labels. Use the exact strings, prefix included.

| Role                  | Label                        | Meaning                                                                                  |
| --------------------- | ---------------------------- | ---------------------------------------------------------------------------------------- |
| `needs-triage`        | `01.status: needs-triage`    | Unclear whether the next step is an agent, a human, or a conversation with the maintainer. |
| `needs-info`          | `01.status: needs-info`      | The agent needs information from a human before work can start.                          |
| `ready-for-agent`     | `01.status: ready-for-agent` | Fully specified; a fresh agent session can pick it up as written.                        |
| `ready-for-human`     | `01.status: ready-for-human` | Requires a human: implementation, design or a decision.                                  |
| `in-progress` (extra) | `01.status: in-progress`     | An agent session has taken it up.                                                        |
| `blocked` (extra)     | `01.status: blocked`         | Work started, then something came up; waiting on a new decision, another issue or a PR.  |
| `wontfix`             | `01.status: wontfix`         | Will not be actioned.                                                                    |

`in-progress` and `blocked` are not triage roles. They exist for agents to track their own work.

## Rules (mandatory)

- Every issue carries exactly one status label, from creation to close. If it would carry two, flag it and ask.
- Creating an issue: apply `ready-for-agent` if a fresh session could pick it up as written, `ready-for-human` if it needs a human, `needs-info` if you lack information, otherwise `needs-triage`.
- Starting work on an issue: set `in-progress` first.
- Abandoning work: set `ready-for-agent` or `needs-triage`. Hitting a wall: set `blocked` and say what it waits on (a decision, another issue, a PR).
- Closing an issue: remove its status label.
- Exception: issues with the Wayfinder issue field set take no status label.
- Every triage comment starts with `> *This was generated by AI during triage.*`

When a skill mentions a role, use the corresponding label string from the table.
